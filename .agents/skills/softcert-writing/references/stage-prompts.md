# 软著材料阶段提示词

每段都以目前案卷、原件清单、目标版本、办理范围和实际应交件为输入。取已有阶段产物继续。回报结论时给能打开的文件和位置。

## 1. 清点原件与核定范围

> 保存当前用户原话，核对网页给出的办理方式、应交材料和格式。只要单件、已有稿只审、指定写入 Word 副本和明确三件套各按本次意图处理。“源程序交存”“程序鉴别材料”都核对为源码项，保留具体件型及 PDF 要求。需求变更时，核对新增、撤销、保留项，并使用当前办理方案编号。“请审核我提供的操作材料”直接核原件，将无凭证的实操声明退回。只有确有新写、交付或修订的指令时进入相应写入路径。遇到实质歧义再确认。

> 阅读上传回执及可读原件，结合文档内容及其在发布包中的路径确认材料用途。记录作者填写稿、软件本身的使用说明、开发资料和第三方依赖各自可佐证的事实。列出本次应交文件、能直接确认的名称和版本、冲突及缺件。申请人填写稿的字段和功能尽量按原字段定位。TeX 手册按章节读取正文，保留源行。扫描命令、快捷键和路径存疑时，回到原页同一位置复读，记录物理页码、首遍字样、复读候选及对应的原页指纹。仅追问会改变起草、交存范围或审核的资料。

## 2. 先确认事实和同版实操

> 逐项核对功能、角色、前置、操作、预期和实测结果，并记录原文字段、页行、源码路径行号或同版证据。实操结论至少复核版本探针、软件包指纹、记录与结果文件。GUI 核操作入口、可观察结果、截图和随附实物。命令行核实际输出中的字面。独立分析器列出的功能、命令或默认版本保留为候选，回原件确认后使用。冲突或欠证的条目标明缺口。

> Python 源码发行包从归档内的顶层 PKG-INFO 核名称、版本及运行依赖，保留字段行号。生成的 egg-info 副本及同根同版的重复声明无需重复认定。若同版 CLI 凭证实际覆盖从解压目录执行的模块入口、版本和帮助，在说明书写明随包归档、工作目录、命令和观察结果。重复的发行 README 保留作参考，正文按已核动作编排。程序及分发构建脚本与运行数据、存根、元数据、文档和测试分别核范围。

## 3. 起草、修订与源码交存

> 网页实操先核同版证据中响应路径、文件 SHA-256 与源码归档或固定上游。记录实际入口，以及语言文件、样式、图标、编译产物和第三方依赖的逐件取舍。有实质程序逻辑的已核入口排在前部。补入文件务必关联可复查的原件、固定提交和实际运行指纹；明确交存版本、范围及重新计算的卷别。

> 静态网页的同版绑定依归档指纹、完整提交、作者 README 版次和浏览器实际响应指纹。证据支持从解压目录打开文件时，在实际手册列出随包原件、目录、入口及结果校验方法。引用运行资源范围时，标出取件包中的实际文件「源码行号映射.json」及字段 `runtime_resource_scope`。嵌入资源只有明确署名、原始数据格式或逐字节重复等证据才能排除，记原件 SHA-256、原行范围和具体依据。有交存变更时重新核算有效源行、连续页和卷别。

> 构建映射中的文件名和扩展名以归档真实路径为准。底稿中的源文件总数、上传与同版补充来源及逻辑页数逐项与交存映射对应。保留作者原报数量和出处，申报源码量由开发方按申报范围核准。

> 给申请表和说明书使用同一批已确认事实。申请表概括真实软件和主要功能。使用说明书将已证实的动作写成可照做的步骤，列前置、实测结果、版本与证据。同版 GUI 实操按步骤嵌入核过指纹的截图，对应操作、结果和图号，以用户操作为正文。原文的功能列表和兼容性保留在静态资料及源行。涉及数据处理或服务器行为的原文声明，列出处和待核的部署环境或实测证据。只改可编辑副本。自备源码册核原件页数、编排和与同版快照的对应关系。交存范围确认后按适用规则编排，保留连续页和源码映射。常规版式容不下长行时先试紧凑版式；逐行追溯原件，仍按同一有效源码行数与回读标准复验。两种版式均无法完整呈现时，保留原件并说明实际排版障碍。

## 4. 只读审核与取件

> 照终件的启动步骤从交付包取出实际所需材料，使用指定目录、启动命令和访问入口复走，检查界面就绪。逐件核对源码范围清单与实际交存映射、补充来源、前后卷及附件指纹。没有已验证的启动入口时保留明确缺口。

> 用本次案卷修订、办理方案、运行配置和审核回执核对取件。只审任务沿自备件原字节和差异报告取件。修订任务逐件区分原件与可编辑副本。以实际下载说明书独立复走必要操作，并记录能否完成。

> 逐件对应预检应交清单、审核回执与实际下载包。独立打开 PDF、可编辑稿、源码册及佐证，核名称和版本。核 PDF 的逐页有效正文、实际动作、图号与原截图，以及可辨认的原件页行引用，长路径可回可编辑稿查全。抽核底稿的主要功能和说明书实际步骤，记录混入的依赖介绍、构建命令等文字的具体位置。源码交存逐卷核范围与实际页行映射。缺经过终检的交存 PDF 时，在 R1 和 R4 记录缺的卷及原因，在可编辑草稿旁写清其用途。逐项写出 R1–R7 判定、证据位置和最早应返工环节。证据中的动作未进入实际说明书时记录内容缺失。材料冲突、错误版本、换过的证据或过期回执保持待核。检查实际取件哈希，并给用户能据此修改的缺口清单。申请人、身份证明、权属和签章缺证时标待补，由经办人核对。

## 5. 复验与补件

> 补正逐项登记通知原件的文件指纹和页码、责任人、所需证明、影响的材料及当前核验。补件后在网页重新关联当期原件，核对旧 ZIP 和单件回执失效。历史答复和整理稿保留各自出处，实际办理状态随机构回执更新。

> 标明补的是原页、版本、实操证据、正文还是经办证明，复用其余有效材料。修订后在同一入口重新取件，复查原反例和改到的文字、页码或证据。测同名换件时记录新案卷修订和旧回执被拒的实测结果。报告说明哪些结果来自程序、哪些经过实际文件审读、哪些需要经办确认。
