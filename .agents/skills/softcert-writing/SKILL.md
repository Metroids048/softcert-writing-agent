# 软著材料整理与验收

先读项目 [STATUS](../../../STATUS.md)、[主流程](<../../../docs/01 主流程与架构.md>)和[七项判据](<../../../docs/02 七项验收与回归样本.md>)。优先沿用已有案卷、原件、失败件和取件回执。用户要新写、修订、自备件复核还是补正，决定本次应交件和允许写入的文件。“请审核我提供的操作材料”属于只读核对，验本案已提供的原件；同一句明确还要新写或写回时按相应任务处理。

1. 在网页上传原件，确认目标软件、版本、办理方式和应交件。逐件保留用户明确的类别、格式和排除项。改需求后回看预检中的新增、撤销、保留和需确认项，按当前结果继续。看预检是否真的读到了申请人提供的填写稿、手册、源码和实操。扫描存疑时回原页。版本或范围冲突时记录位置和所需材料。
2. [按阶段提示词](references/stage-prompts.md)整理出处和结论。优先使用原件和已绑定同版的操作证据。外部分析器输出的功能、版本和命令均需回查。扫描命令存疑时并列保留首遍识别和原页复读结果。实操缺失时可从静态材料起草，功能列表与操作步骤分开，验证状态随稿保留。
3. 用工作台生成申请表和说明书可编辑底稿，或只读复核自备件。写回已有稿只改副本。明确动作、前置和可观察结果，保留原出处。源码须先确认版本、文件顺序和交存范围，再调用项目固定排版入口。
   对网页软件，用同版浏览器响应和原件指纹确认实际入口及界面资源。程序入口和有实质功能的自有资源纳入交存并重新分页。对语料、样式、图标、构建输出和依赖逐件记录范围与依据。构建依据指到归档中的实际路径及文件指纹，底稿区分上传源码与核验后补入的同版源码。手册应给出可取得的材料、启动目录、命令或操作、访问入口和就绪状态，缺证据时标待补。
4. 从同一案卷下载审阅包和已放行单件。打开实际取件核对内容、源码页行、操作结果和来源，并用终检回执核对指纹。逐页查 PDF 正文和出处。按实际使用者的任务看说明书能否照着做，同时核用途和步骤是否混入开发或依赖资料。源码排版受阻时核原件是否保全和回执是否指到具体障碍。定位重复问题时，先复现旧失败，再在同一入口验证修复。换版、换件或补证据，从最早受影响环节复验。
5. 交付可编辑底稿、已审核文件和待核清单，请用户依据真实软件复核修改。按[冻结验收模板](<../../../docs/07 成品与提交验收模板.md>)对实际取件逐案审读。内部验收须应交齐全、达到 85 分且无关键错误。缺独立全项证据标待验。分别说明七项内部质量判断、经办确认项和实际办理状态，正式办理状态随实际回执更新。

项目总结从当前网页审核回执及实际下载件一并取证。每类应交件列出包内路径或缺项，源码前后分册逐卷列。回执里的名称和版本要与申请表、说明书和交存页眉核对，软件包标识单独追溯。源码草稿及原件可随包留查，缺少通过终检的 PDF 时，R1 与 R4 同时记录缺项。

阶段提示词供执行此 Skill 的 Agent 使用。本地网页由 [server.mjs](../../../app/server.mjs) 执行识别、生成、终检和取件。网页预检的办理方案、运行配置、当前案卷修订和审核回执随可取材料核对。需要改工作流程时，核对程序的阶段交接和实际网页回归。
